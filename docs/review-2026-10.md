# Code review 2026-10: duplication, standards, scalability

RV3 (BashCutPro code review round, 2026-10-23), started on `main` ee7bd19. Scope: all 8 plugins, their shared code,
the test fakes, `tools/`, `tests/`, `registry.json` + manifests, the README. Refactors in this round do not change
behaviour; fixes that would change it are proposed tickets (`RP*`) at the end.

**Coverage.**
- **Shared code**: every shared-pattern file was read and diffed across all plugins: `plugin.py`, `mcp.py`,
  `settings.py`, the `progress` / `emit` / `main` / `connection_args` / `connect` / `save` parts of every `cli.py`,
  the `timeline.py` signatures, `bashcut_models.py`, `tools/*.py`, `tests/*.py` and the per-plugin `test_manifest.py`.
  Findings: D, I, S, X and R below.
- **Domain modules**: a second pass read the rest line by line. That is every other module of the 8 packages, the
  `resources/scripts/fetch_*.py`, `hyperframes/lib/*.js` and the per-plugin tests. Findings: M below.
  - Marked **verified** where the claim was re-checked against the code while writing this document (the bugs that
    became tickets, and all the dead code).
  - The rest are as reviewed; whoever takes the ticket re-checks them first.
- Not reviewed: the hyperframes `examples/*.html` and the tests' `fake_filmcraft.py` beyond D7.

**How the host installs a plugin** decides what may be shared. The host (`crates/bashcut-plugin-host/src/install.rs`)
copies one plugin folder (`registry.json` `source.path`) into `<data dir>/bashcut-plugins/<id>/` and runs
`entry.command` there. Nothing above the plugin folder is installed except `models.json`.
- So a plugin must stay self-contained, and shared code is *vendored*: an identical copy in each plugin, kept equal by
  a check, the way `bashcut_models.py` already was.
- A shared Python package imported from outside the plugin folder would break installed plugins.
- RV3 made this the general mechanism: canonical copies in `tools/`, `tools/sync_shared.py` writes them, and
  `tests/test_shared_copies.py` fails on a stale copy.

### Scalability: what adding a 9th plugin cost

Before RV3:
1. Copy a plugin folder, rename the package.
2. Replace the id in `bashcut-plugin.json`, `plugin.py`, `mcp.py` (`clientInfo`), `settings.py` (`PLUGIN_ID`) and
   `__init__.py`. Nothing listed the places, so a missed one went unnoticed.
3. Keep one of three `emit` / stdio styles. Write a fake engine from one of the 8.
4. Add the registry entry, a README row and a README test line by hand.

**After RV3:**
1. Run `python3 tools/new_plugin.py <name> --title … --summary … --vi-title … --vi-summary …`. It makes a plugin
   that passes every check as it is (`tests/test_new_plugin.py`), and its registry entry.
2. Replace the example action with the plugin's own and add the README row.
3. The shared code (`bashcut_cli.py`, `bashcut_settings.py`, `mcp.py`) comes with it and stays in step through
   `sync_shared.py` + `test_shared_copies.py`. `check_all.py` finds its tests.

### Domain modules (second pass)

Line numbers are those of `main` after RV3's refactors.

**Duplication**

- **M1. The Gemini / OpenAI client is written twice.**
  - Copies: `translate-captions/translate.py:174-328` and `image-gen/service.py:34-202`.
  - Duplicated parts: `is_local`; the key, endpoint and https checks; the HTTPError → auth / 429 / 5xx
    classification; the Gemini `candidates` / `finishReason` parsing.
  - The retry policies have already drifted apart (M20). → RP10.
- **M2. Five error classes with the same `(code, message)` shape.** `TranslateError`, `ImageError`, `PictureError`,
  `LibraryError` and `AppError`. One `bashcut_cli.PluginError(code, message, data=None)` would do. → RP11.
- **M3. BMP and PNG code in two to three plugins.**
  - BMP reading: `translate-captions/bmp.py` `read_gray` and `vision/images.py` `read_bmp`; only vision validates.
  - BMP writing: `write_bmp` is byte-identical in both (X4).
  - PNG writing: `image-gen/picture.py` `encode_png` and `vision/images.py` `write_png`.
  - PNG size: `hyperframes/render.py` and `vision/images.py`; one returns `None`, the other raises.
  - → RP14.
- **M4. Frame-sampling helpers in translate-captions `cover.py` and `vision/timeline.py`.**
  - `footage_items` is identical.
  - `video_clips` differs: other signature, and only vision raises when nothing matches.
  - `sample_times` differs: `cover.py` ignores clip `speed`.
  - → RP14.
- **M5. Private-venv `setup` written three times.** vieneu-tts `cli.py` (`setup_steps` with a uv fallback), resources
  `cli.py` (the same), vision `cli.py` (neither the Python 3.10 check nor the uv fallback). → RP13.
- **M6. "Read JSON from a file or `-`, errors are `bad_args`" helpers.** translate `load_json`, vision
  `read_answer`, image-gen `read_json`, hyperframes `json_arg`, library `json_arg`. Translate's raises a bare
  `ValueError`, so it exits 1 where the others exit 2. → RP11.
- **M7. Default output folder.** "`--out`, else `<project dir>/<sub>`, else `./<name>`" in image-gen, vieneu-tts,
  align, hyperframes `out_dir` and vision `project_folder`. → RP11.
- **M8. The ticks-per-second constant `254016000000`.** In `captions.py`, `cover.py`, `vision/timeline.py`,
  `align/texts.py`, `library/engine.py` and the `timeline.py` files. → RP6.
- **M9. About nine file-name sanitisers.** In image-gen, vieneu-tts, library (two different ones), resources
  `search.py` and four `fetch_*` scripts. `fetch_luts` has no fallback (M28). → RP16.
- **M10. Resources scripts: six HTTP getters.** `fetch_stock.get` retries; `fetch_facts.get` has its own retries;
  `fetch_font`, `fetch_fonts`, `fetch_luts` and `fetch_lottie` (`post`) have none. → RP16.
- **M11. Resources scripts: five `bashcut()` subprocess wrappers.** In `fetch_stock`, `fetch_audio`, `fetch_luts`,
  `fetch_facts` and `fetch_fonts`; two of them lack the stale-revision retry. → RP16.
- **M12. Resources scripts: the "library add → place" block, five times.** In `fetch_stock`, `fetch_audio`,
  `fetch_emoji`, `fetch_illustrations` and `fetch_logos`; `fetch_logos.save` is the most general version. → RP16.
- **M13. More copies inside the resources scripts.**
  - Licence and pick helpers: `fetch_audio` `parse_pick` / import / `write_licence` repeat `fetch_stock` and
    `resources_plugin/licences.py`.
  - Emoji and Lottie: `score` / `rank` / `slot_name` / `NOTO_INDEX` are repeated between the two scripts.
  - `svg_shape` in `fetch_logos` repeats `fetch_illustrations`.
  - The macOS-default `shared_dir()` appears six times (M30).
  - → RP16.
- **M14. ffmpeg discovery two ways.** `image-gen/picture.py` reads `$FFMPEG`; hyperframes `runtime.py` uses a setting,
  then PATH. → RP13.
- **M15. Brand / font-face injection twice in JS.** `hyperframes/lib/diagram.js` `brand` and `lib/amenity-map.js`
  `applyLook`. → RP12.
- Not duplicated (checked): SRT parsing and writing (only `align/texts.py`), and JSON-from-model parsing (only
  `translate.parse_lines`).

**Inconsistency**

- **M20. Retry policies differ for the same service.**
  - translate-captions retries network errors, honours Gemini `retryDelay` and treats the daily quota as final.
  - image-gen fails at once on a network error and uses fixed 5 / 15 / 30 s waits on 429.
  - image-gen also has no `wrong_model` check and no `check-key` command.
  - → RP10.
- **M21. Two hand-off shapes.**
  - vision: code `handoff`, with `data.then` and a template `answer`.
  - translate-captions: code `no_key`, an `answer` sentence, and no `then`.
  - → RP11.
- **M22. Setup subprocess output goes to different places.** hyperframes sends it to stderr; the others to stdout
  (M40). → RP13.
- **M23. `timeline.place` units differ.** vision passes `time` (ticks); library and the timeline helpers pass
  `seconds`. → RP6.
- **M24. Temp folders.** vision cleans up with `try/finally`. translate-captions `cover.detect_clip` makes one per clip
  and never removes it. → RP14.
- **M25. Openverse licence names differ.** `fetch_audio` says "Public Domain Mark"; `fetch_stock` says "CC PDM 1.0".
  → RP16.
- **M26. JS JSON parsing.** `diagram.js` calls `JSON.parse(v.data)` unguarded; `amenity-map.js` has a safe
  `parseJSON`. → RP12.
- **M27. vieneu-tts usage errors.** `synth.py` raises `ValueError` for bad input ("line N has no text"), so the plugin
  exits 1 instead of 2. → RP11.
- **M28. `check_registry.py` has two weak checks.**
  - `check_bool_defaults` is a substring search over all the sources. Checking against `build_parser()` would be
    stronger.
  - The first clause of the `handoff.then` check is redundant.
  - → RP9.

**Likely bugs**

- **M40, verified. Setup output breaks the result.** vieneu-tts, vision and resources `cmd_setup` run pip / uv with
  stdout inherited (`subprocess.run(step)`). Their output then lands before the one JSON object a host parses.
  hyperframes already sends it to stderr. → RP13.
- **M41, verified. hyperframes ignores the sequence frame rate.**
  - `sequence_fps` looks for a top-level `fps` / `frameRate` / `timebase` in `sequence_inspect`.
  - The engine reports `settings.frame_rate {num, den}`, which vision and resources read.
  - So renders and `--frame` use 30 fps on 24 / 25 / 60 fps sequences. The fake sequence has no rate, so tests miss it.
  - → RP12.
- **M42. hyperframes render records collide.**
  - `record_path` uses `splitext`, so a folder name containing a dot shares a record with another graphic.
  - The format is not in the digest, so png and mov renders of the same graphic overwrite each other's `placed` list.
  - → RP12.
- **M43, verified. One failed download stops the image-gen batch.**
  - The OpenAI URL answer is fetched with a bare `urlopen` (`service.py:170`).
  - `URLError` is an `OSError`, which `generate_batch` does not catch (it catches only `ImageError` / `PictureError`).
  - So the batch ends as `failed`, and `images.json` is never written for the pictures already saved.
  - → RP13.
- **M44, verified. A Tesseract timeout crashes vision.** `ocr.py:56` uses `timeout=120`. `TimeoutExpired` is not an
  `OSError` or `ValueError`, so the plugin ends with a traceback instead of JSON. → RP14.
- **M45. `ocr-apply` mixes time types.** It sorts on `time`, and an agent's string time next to stored ints raises
  `TypeError`. → RP14.
- **M46. A truncated BMP crashes `cover`.** `bmp.read_gray` does not validate, so `struct.error` / `IndexError`
  escape as a traceback. → RP14.
- **M47. `apply` says "0 had no translation" when every kept line was stale.** In translate-captions. → RP15.
- **M48. resources `fetch` reports `script_failed` after it already imported and saved.** → RP15.
- **M49. library pack import trusts the pack's own `sha256`.** It never recomputes it, so a wrong hash makes it skip
  or duplicate items. → RP15.
- **M50. `fetch_luts` collides LUTs by slug.** The slug has no fallback, so LUTs whose names differ only in case,
  punctuation or non-ASCII letters count as "known" and are skipped. `--limit` also skips the checksum-verified
  RawTherapee zip. → RP16.
- **M51. Contact-sheet labels have no Vietnamese glyphs on Windows and Linux.** `fetch_stock.label_font` lists only
  macOS fonts. → RP16.
- **M52. Agent frames and temp folders pile up.** vision `vision-frames/` and translate-captions `bashcut-cover-*`.
  → RP14.
- **M53. Transient keys end up in the `.graphic.json` record.** hyperframes writes `reused` / `warnings` into it.
  → RP12.

**Scalability**

- **M60. The align DP can blow up in memory.** `align.path` keeps `cost` / `back` as dicts keyed by tuples. A short
  script against a long transcript gives about 10 M cells per dict. → RP17.
- **M61. Downloads are held in RAM, and the size cap is checked afterwards.** In `fetch_stock.get` and
  `search.download`. → RP17.
- **M62. `Math.max(...xy)` over long OSRM routes.** In `osm-map.mjs`; it can exceed V8's argument limit. → RP12.
- **M63. The library index has no locking.** Concurrent runs (batch packs) lose `uses` / `recent` / `add` updates.
  → RP15.
- **M64. Kind and synonym tables kept in step by hand.** Amenity kinds in `amenity-map.js` and `osm-map.mjs`; the
  `SYNONYMS` tables of emoji, illustrations and lottie. → RP12 / RP16.

## Proposed tickets

Prefix `RP`.
- Every ticket that changes plugin code bumps the plugin's `version` in `bashcut-plugin.json`, its `__version__` and
  `registry.json` (`check_registry.py` checks all three).
- Shared code is changed in `tools/` and copied with `tools/sync_shared.py`, never edited in a plugin copy.
- **Same files:**
  - RP1, RP6 and RP11 touch every plugin's package.
  - RP10, RP11, RP13 and RP14 touch the same `cli.py` files.
  - RP12, RP16 and RP17 are plugin-local and can run in parallel with each other.
  - Order: RP11 → RP1 → RP6 → RP13 → RP14; RP5, RP7 and RP9 any time.

### RP1: one canonical MCP client, real `clientInfo.version`
- **Owns:** `plugins/*/*/mcp.py`, `tools/bashcut_mcp.py` (new), `tools/sync_shared.py`, `tests/test_shared_copies.py`,
  `tools/new_plugin.py`, the versions of all 8 plugins.
- **Do:**
  - Make the MCP client a vendored top-level module (`bashcut_mcp.py`, like `bashcut_cli.py`).
  - Have it take the plugin id and version from its caller (`McpClient.connect(..., client=(PLUGIN_ID,
    __version__))`).
  - Each package's `mcp.py` shrinks to that import, or goes away.
- **Acceptance:** one copy in `tools/`; `clientInfo` shows each plugin's id and real version (I2, a behaviour change
  in the handshake only); every check green.

### RP5: shared test fake core
- **Owns:** `plugins/*/tests/fake_filmcraft.py`, a canonical fake core in `tools/`, `tools/sync_shared.py`,
  `tools/plugin_template/tests/`.
- **Do:** put the JSON-RPC loop, `initialize`, `command_run` / `command_batch` and the state file in one vendored test
  module. Each plugin's fake registers only its own tools and commands.
- **Acceptance:** every plugin's tests green with no plugin code change.

### RP6: vendored timeline helpers and the ticks constant
- **Owns:** the 5 `timeline.py`, a new `tools/bashcut_timeline.py`, the `TPS` constants (M8), `tools/sync_shared.py`.
- **Do:**
  - Move `import_files`, `ensure_track(kind, name)`, `overlaps`, `track_index`, `frame_ticks` and `TPS` into the
    shared module.
  - Decide `timeline.place` units once (M23).
- **Acceptance:** the fake engine's recorded calls are unchanged (tests compare them); every check green.

### RP7: one manifest ↔ CLI test
- **Owns:** `tests/test_manifest_cli.py` (new), the per-plugin `test_manifest.py`, `library/tests/test_library.py`,
  `resources/tests/test_plugin.py`, `tools/plugin_template/tests/test_plugin.py`.
- **Do:** one repo-level test over every plugin: actions == `cli.COMMANDS`, every param flag accepted, connect
  flags on `needs: project` actions. Remove the duplicated parts per plugin.
- **Acceptance:** the same assertions run for all plugins, translate-captions' missing check included (D10).

### RP9: `check_registry.py --fix` and stronger checks
- **Owns:** `tools/check_registry.py`, `tests/test_registry.py`, README.
- **Do:**
  - `--fix` writes the registry fields derived from the manifest, and `__version__`.
  - `check_bool_defaults` checks the real parser (M28).
- **Acceptance:** a version bump is one manifest edit plus `--fix`; without `--fix` the check stays strict.

### RP10: one AI-service client for translate-captions and image-gen
- **Owns:** `translate-captions/translate.py`, `image-gen/service.py`, a new `tools/bashcut_ai.py`, both plugins'
  tests and versions.
- **Do:**
  - Move `is_local`, the key / endpoint checks, the HTTP error classification and one retry policy into a vendored
    `Client(kind, key, model, endpoint).send(...)` (M1).
  - image-gen gains network retries, Gemini `retryDelay` and `wrong_model` (M20).
- **Acceptance:** both plugins' tests green; new tests for the retry policy; the behaviour change for image-gen
  written in its README.

### RP11: shared plugin errors, JSON input, output folder, hand-off shape
- **Owns:** every `cli.py`, `tools/bashcut_cli.py`, translate-captions `translate.py`, image-gen `service.py` /
  `picture.py`, library `library.py`, vieneu-tts `synth.py`, the skills that describe hand-offs.
- **Do:**
  - Add `bashcut_cli.PluginError` (M2), `read_json(path_or_dash)` (M6), `out_dir(args, sub, fallback)` (M7) and a
