# Code review 2026-10: duplication, standards, scalability

RV3 (BashCutPro code review round, 2026-10-23), on `main` ee7bd19. Scope: the 8 plugins' shared code (`plugin.py`,
`cli.py` result/progress/UTF-8 handling, `mcp.py`, `settings.py`, `timeline.py`, `bashcut_models.py`), the test fakes,
`tools/`, `tests/`, `registry.json` + manifests, the README. Behaviour must not change in this round; fixes that would
change it are proposed tickets (`RP*`) at the end.

**Coverage.** Every shared-pattern file was read and diffed across all plugins (`plugin.py`, `mcp.py`, `settings.py`,
the `progress` / `emit` / `main` / `connection_args` parts of every `cli.py`, `timeline.py` signatures,
`bashcut_models.py`, `tools/*.py`, `tests/*.py`, the per-plugin `test_manifest.py`). The plugins' domain modules
(`translate.py`, `synth.py`, `picture.py`, `render.py`, `backends.py`, `library.py`, `search.py`, `scripts/fetch_*.py`,
…) were only surveyed for the shared patterns above, not reviewed line by line: that is RP8.

**How the host installs a plugin** (decides what may be shared): the host copies one plugin folder
(`registry.json` `source.path`) into `<data dir>/bashcut-plugins/<id>/` and runs `entry.command` there; nothing above
the plugin folder is installed except `models.json`. So a plugin must stay self-contained: shared code is *vendored*
(an identical copy per plugin, kept equal by a check), the way `bashcut_models.py` already is. A shared Python
package imported from outside the folder would break installed plugins.

### Scalability: what adding a 9th plugin costs today

1. Copy a plugin folder (usually translate-captions or library), rename the package, replace the id in
   `bashcut-plugin.json`, `plugin.py`, `mcp.py` (`clientInfo`), `settings.py` (`PLUGIN_ID`), `__init__.py`.
2. Delete the old plugin's commands, keep `progress` / `emit` / `main` / `connection_args` (choosing one of the I1
   styles), write a new `fake_filmcraft.py` from one of the 8.
3. Add the registry entry by hand (fields repeated from the manifest; `check_registry.py` catches mistakes), a README
   row and a test line in the README.
4. If it downloads: add `models.json` entries and a copy of `bashcut_models.py`.

There is no scaffold and no list of the ids to replace, so a missed `clientInfo` or `PLUGIN_ID` goes unnoticed (the
new D1 check now catches a stale `mcp.py` body, not a stale id). **RP4** makes this a documented, short path:
`plugins/_template/` (or `tools/new_plugin.py <name>`) with the vendored helpers, a minimal manifest, skill, fake and
test, plus `tools/sync_shared.py` that copies the canonical helpers (D1, D2, D5, D8) into every plugin and a check that
fails when a copy differs, as `check_models.py` does for the downloader.

| # | Where | Why it matters | Proposed fix | Size | Behaviour |
|---|---|---|---|---|---|
| S1 | no scaffold (above) | every new plugin is a copy-and-rename of an old one | RP4 | M | no |
| S2 | `registry.json` repeats manifest fields by hand | `check_registry.py` checks them, but a version bump is 3 edits (manifest, `__init__.py`, registry) | RP9: `tools/check_registry.py --fix` writes the derived registry fields and the `__version__` from the manifest | S | no |
| S3 | README check list (one line per plugin) | grows with every plugin, easy to forget | RP4 (`tools/test_all.py`) | S | no |

## Proposed tickets

Prefix `RP`. Every ticket that changes plugin code bumps the plugin's `version` in `bashcut-plugin.json`,
`__version__` and `registry.json` (`check_registry.py` checks all three). RP1, RP2, RP3, RP4, RP6 all touch every
plugin folder and should run one after another (RP2 → RP3 → RP6 → RP1 → RP4), not in parallel.

### RP1: one canonical MCP client, real `clientInfo.version`
- **Owns:** `plugins/*/*/mcp.py`, `tools/plugin_kit/` (new), `tests/test_shared_copies.py`, versions of all 8 plugins.
- **Do:** canonical `tools/plugin_kit/mcp.py` taking the plugin id and version from the package (`from . import
  PLUGIN_ID, __version__`, `PLUGIN_ID` added to each `__init__.py`); copy it into every plugin; turn the D1 check into
  "byte-equal to the canonical copy".
- **Acceptance:** all `mcp.py` byte-equal; `clientInfo` shows each plugin's id and real version; all tests green on
  Windows and macOS/Linux.

### RP2: vendored result/stdio helper — done in RV3 as `tools/bashcut_cli.py`
- **Owns:** every `cli.py` (`progress`, `emit`, `main`, `connection_args`), new `tools/plugin_kit/bashcut_result.py`
  and its copies, the copy check.
- **Do:** `utf8_stdio()`, `progress(prefix, message)`, `emit(value)`, `connection_args(parser)`, `connect(args)`,
  `EXIT_HANDOFF`, `run(commands, args, errors=…)` mapping errors to exit 0/1/2/3; replace the 8 copies.
- **Acceptance:** results and progress byte-identical before/after on a Vietnamese sample per plugin (a test that runs
  each plugin with a cp1252 `PYTHONIOENCODING` and compares); FX1–FX3 tests green.

### RP3: vendored settings helper (`bashcut_settings.py`)
- **Owns:** the 6 `settings.py`, new canonical copy, copy check.
- **Do:** data dir, plugin dir, settings file, one `SETTINGS` shape `(env, default, secret)`, `resolve`, `venv_python`.
- **Acceptance:** each plugin's settings tests unchanged and green; a new test resolves the same values as before for
  flag / env / file / default on all three OS data-dir rules.

### RP4: plugin template and sync script
- **Owns:** `plugins/_template/` or `tools/new_plugin.py`, `tools/sync_shared.py`, README "Adding a plugin",
  `check_registry.py` and `tools/check_all.py` (ignore `_template`).
- **Do:** scaffold with the vendored helpers, manifest, skill, fake, tests; sync script. (The one-command gate,
  `tools/check_all.py`, landed in RV3.)
- **Acceptance:** `tools/new_plugin.py demo` + registry entry gives a plugin whose tests and `check_registry.py` pass
  with no other edit; README documents it in ≤ 10 lines.

### RP5: shared test fake core
- **Owns:** `plugins/*/tests/fake_filmcraft.py`, new canonical fake core.
- **Do:** JSON-RPC loop, `initialize`, `tools/list`, `command_run`/`command_batch`, state file in one vendored module;
  each plugin's fake registers its handlers.
- **Acceptance:** every plugin's tests green with the new fakes; no plugin code changed.

### RP6: vendored timeline helpers
- **Owns:** the 5 `timeline.py` (hyperframes, image-gen, resources, vieneu-tts, vision), canonical copy.
- **Do:** `import_files`, `ensure_track(kind, name)`, `overlaps`, `track_index`, `frame_ticks`.
- **Acceptance:** fake-engine call sequences unchanged (tests compare the recorded calls); all tests green.

### RP7: one manifest ↔ CLI test
- **Owns:** `tests/test_manifest_cli.py` (new), per-plugin `test_manifest.py`, `test_library.py:204`,
  `test_plugin.py:200`.
- **Do:** one repo-level test over every plugin; remove the duplicated parts per plugin.
- **Acceptance:** the same assertions run for all 8 plugins (library and resources included).

### RP8: line-by-line review of the domain modules
- **Owns:** read-only review; findings appended to this document.
- **Do:** the modules listed under Coverage, for duplication with each other (e.g. key/service handling in image-gen
  and translate-captions, BMP/still export in translate-captions and vision).
- **Acceptance:** findings table + tickets.

### RP9: `check_registry.py --fix`
- **Owns:** `tools/check_registry.py`, README.
- **Do:** write registry fields derived from the manifest (`version`, `name`, `category`, `platforms`, `minAppVersion`,
  `runtime`, paths) and report `__version__` mismatches.
- **Acceptance:** a version bump is one manifest edit + `--fix`; check stays strict without `--fix`.
